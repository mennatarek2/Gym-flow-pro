Architecture

No Tailwind. No new CSS framework. The staff desk is static HTML + vanilla CSS. Shared scripts already inject from apps/web/server.js. Theme belongs there — next to locale and branding.

How it wires
  1. Boot script in <head> (same slot as gfp_locale) reads gfp_appearance and sets html[data-theme] before paint.
  2. shared/theme.css defines semantic tokens and remaps existing --lbg --ls1 --ltp --ls3.
  3. Pages that already use those variables inherit both themes.
  4. html[data-theme="dark"] beats page-local :root { --lbg:#FAFAFA } (higher specificity).
  5. Hardcoded #fff / rgba cream (POS topbar, some cards) get a second pass.
  6. Tenant branding still sets --gfp-brand-primary only — never Success / Danger / Warning.

Audit findings
Tokens exist, Light-only. Canonical palette lives in pos.css :root. Dashboard, Members, Notifications, auth OTP copy their own :root.
Injection point already exists. server.js injects rtl.css, typography.css, gfp-branding.js, early locale script. Theme boot belongs in that early script.
Tenant branding. gfp-branding.js remaps --l500/--l600/--l400. Logo sits on a white 32px pad (safe for dark-unfriendly logos). No light/dark logo pair in Settings today.
Persistence model. Locale is browser localStorage (gfp_locale). Appearance should match: gfp_appearance = light | dark | system. Not a Tenant.Settings field. No new API.
Charts. Dashboard Chart.js. After Accept, series/grid/tooltip colors read CSS variables.
Print already separate. Reports and Z-Report have @media print. Dark Mode must force light tokens in print.
Member App. Flutter, separate frontend. Do not couple. Same semantic principles can be a later Flutter prompt.
Admin Vite app. Placeholder shell, not the live desk. Out of the first implementation pass.
Hardcoded UI colors. Widespread #fff in Offers, Call Sheet, Settings, POS cream rgba, Member 360. Token remap covers most pages; those files need a targeted replace — not a rewrite of business logic.

After Accept — one pass

Not implemented until you Accept. Sequence is global first, then leftover hardcoded colors, then QA. No business-logic changes.

Do
  • Add shared/theme.css + extend the early <head> boot in server.js.
  • Settings Appearance: Light / Dark / System.
  • Persist gfp_appearance (browser). Listen to OS when System is selected.
  • Remap --lbg --ls1 --ltp --ls3 so POS, Reports, Invoices, Attendance, Call Sheet, etc. inherit.
  • Replace leftover UI #fff / cream rgba in POS, Members, Member 360, Offers, Settings.
  • Chart.js colors from CSS variables. Status pills from one badge set.
  • Print stylesheet forces light. Logo keeps the white pad.
Do not
  • Implement Dark Mode inside Call Sheet (or any single page) first.
  • Introduce Tailwind or a theme library.
  • Store appearance on Tenant.Settings (that is Gym Identity).
  • Let brand color override Success / Danger / Warning.
  • Dark-print invoices or Z-Reports.
  • Couple the Flutter Member App. Document tokens later.
  • Change APIs, RBAC, memberships, sales, or attendance logic.
  • Use neon, pure black canvas, or gaming glow (Offers loud UI was already rejected).
