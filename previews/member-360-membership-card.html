Verdict

Yes — redesign this card. White-on-white was rejected as crowded (profile card + tab pane + another white tile). Do not go back to the dark hero either.

Surface Recessed sage panel on the white Membership tab, status color on a left rail. Facts are one quiet line, not a grid of mini-cards. Lime only on the primary action.
What is actually wrong (from code, not taste)
  • Progress bar is inverted. Width = days remaining ÷ duration. Day 3 of a 30-day plan fills ~93%. Staff read a full bar as “almost over.” It is not a streak. Streak belongs in the Member App if ever — not on the desk.
  • “Waiting for payment” is nearly invisible. Banner uses --wrn100 / --wrn500, which are not defined on Member 360. Invalid CSS → dark text on a dark card.
  • Pending has no badge style. .ms-st-badge.pending does not exist. Gateway pending looks like a quiet active membership.
  • Refresh status floats in empty space because the warning block collapsed. Duplicate Refresh also sits under Renew.
  • Amount paid EGP 0 + Fawry is true for an unpaid gateway membership. The card never says that first. Dates are baked before payment, so the bar still runs.
  • Invitation quota is not on this card. Quota is a covering membership fact (Plan.ReferralInviteQuota minus creates on that Id). The profile chip is a glance only; the Invitations tab is the work surface. The membership card should show remaining / total for this period.

What the redesigned card is

The operational answer to: What plan is this person on, can they train, how long is left, what is still unpaid, how many invitations does this period have?

  • Recessed sage card on the white tab — not a second white tile, not a dark island.
  • Status in human words: Waiting for payment / Active / Frozen / Expired / Cancelled.
  • Pending: amber strip with contrast, one Refresh status. No period bar. No “days remaining” until covering starts.
  • Active: N days left as the number. Bar = time used (elapsed), labeled “used X of Y days.”
  • Facts: Invitations remaining / total on this covering plan. Sessions left if session pack. Paid + method. Frozen until if frozen.
  • Do not copy Invitation CRUD here. Do not add a second quota. Do not treat Amount Paid as “paid in full” after Collect Payment (that snapshot stays first payment).
  • Lime only on the primary action for the state (Refresh when pending, Renew when covering).

Do not

  • Gamify with a streak / fire icon.
  • Put Collect Payment on this card (that is member outstanding on the profile).
  • Show Guest Pass / Referral Code.
  • Use Plan.InvitationQuota (retired guest-visit column).
